# AGENTS.md — working in the my-aidlc repository

This file guides AI coding agents contributing to my-aidlc itself. For using
my-aidlc in a project, see [README.md](README.md) and
[docs/guide/01-getting-started.md](docs/guide/01-getting-started.md).

## What this repository is

my-aidlc is one harness-neutral core plus thin per-harness projections:

- `core/` — the methodology (phases, stages, agents, scopes, protocols) and the
  Node.js engine under `core/tools/`.
- `harness/<name>/` — a manifest and authored files for PI Agent, Codex CLI,
  and Claude Code.
- `scripts/` — packaging, installers, and lint.
- `tests/` — the test suite.
- `dist/` — generated; never edit by hand.

## The golden rules

1. **Edit `core/` or `harness/<name>`, never `dist/`.** `dist/` is generated by
   `node scripts/package.mjs`.
2. **The engine owns state.** Never advance a stage, write a state field, or
   append an audit row outside `core/tools/lib/`. The conductor reports
   outcomes; the engine transitions.
3. **Humans own decisions.** No agent may merge, approve, or silently choose an
   architecture, a scope, or a release.
4. **Methodology is data.** Add a stage by adding a Markdown file with
   frontmatter, not by editing the engine.

## Development commands

```bash
node scripts/package.mjs          # build all harnesses into dist/
node scripts/package.mjs --check  # determinism guard: fail if dist is stale
node scripts/lint.mjs             # structural checks on the methodology
node tests/run-tests.mjs          # unit + integration tests
```

Run all four before considering a change complete.

## Adding or changing a stage

1. Create or edit `core/phases/<phase>/stages/<slug>.md`.
2. Frontmatter must include `slug`, `phase`, `execution`, `condition`,
   `lead_agent`, `produces`, and `consumes`. Conditional stages need a
   `condition`. See [docs/reference/02-methodology.md](docs/reference/02-methodology.md).
3. Reference only agents that exist in `core/agents/` and only consumed
   artifacts that some stage produces. `scripts/lint.mjs` enforces both.
4. If the stage is not covered by an existing scope's `phases`, add it to a
   scope's `include`.

## Adding an agent

Add `core/agents/<slug>-agent.md` with `name`, `display_name`, `tier`, and a
`description`, then reference it from a stage. An agent unreferenced by any
stage (other than the cross-cutting composer) fails lint.

## Adding a harness

1. Create `harness/<name>/manifest.mjs` exporting a manifest.
2. Add `harness/<name>/onboarding.md` and native config files.
3. Register the harness dir/invoke strings in `core/tools/lib/paths.mjs`.
4. Run `node scripts/package.mjs <name>` and add it to the README table.

## Code conventions

- Node.js ESM (`.mjs`), no runtime dependencies.
- One module per concern under `core/tools/lib/`.
- Keep the engine deterministic: no random, no wall-clock-dependent decisions
  except timestamps in the audit log.
- Prefer explicit errors over silent fallbacks.

## Reporting

The audit log is append-only. Event names come from
`core/knowledge/audit-format.md`. Do not invent event names.
