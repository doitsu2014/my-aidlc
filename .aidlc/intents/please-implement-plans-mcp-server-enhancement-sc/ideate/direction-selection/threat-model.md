- Purpose: STRIDE threat model for the selected direction (Option A "Lean hand-rolled", with the owner-decided dual-era protocol: legacy `initialize` plus the stateless 2026-07-28 flow): the `application` facade and the `dtech-aidlc-mcp` stdio server with four tools. Residual risks wait for the owner at the solution-direction gate.
- Status: Draft - pending solution-direction gate. Mitigations cite decisions in [decision-record.md](decision-record.md); they are Recommended unless the decision is owner-decided.
- Stage: Ideate / direction-selection (decision-facilitator). Companions: [architecture-design.md](architecture-design.md), [scope-boundary.md](scope-boundary.md), [recommended-direction.md](recommended-direction.md).
- Sources: threat research pass of 2026-11-27 with experiments in `<spike>/threat-researcher/limits/`; code at commit 69cab5a (Observed 2026-11-27); MCP spec 2025-11-25 tools page (Observed, https://modelcontextprotocol.io/specification/2025-11-25/server/tools, fetched 2026-11-27); MCP schema 2026-07-28 (`schema.json`, `schema.ts`) and schema 2025-11-25 saved under `<spike>/decision-facilitator/web/` (Observed, re-checked 2026-11-27); the dual-era spike `<spike>/decision-facilitator/srv/src/main.rs` with host captures `cc-dual/frames.log` and `ts-dual-auto.log` (Observed); `<spike>/host-compat/dsh/` (copied host docs and sources, Observed, not run). `<spike>` = `/private/tmp/claude-501/-Users-doitsu2014-workspaces-doitsu-technology-my-aidlc/dbbd0152-2f7e-4566-a23e-0dd698cbab3c/scratchpad/spike/`.
- Ratings: likelihood and impact are qualitative Estimates. TH-nn, A-n, B-n and E-n are local row labels in this document, not registry identifiers.
- Residuals for the owner at the gate: TH-01 High (already owner-accepted, Q6); TH-04, TH-05 and TH-16 Medium; TH-15 Low likelihood with High impact. Everything else is Low or Low-Medium, including the modern-path rows TH-19 and TH-22 that cover the owner's dual-era decision. Two residuals depend on an unverified Assumption: whether Claude Code and DeepSeek Harness ask the user to confirm MCP tool calls by default.

## Assets
- A1. Gate decisions and approver records: `.aidlc/intents/<id>/state.json` and `gate.decided` audit rows.
- A2. Workflow state: the pointer `.aidlc/state.json` and per-intent state.
- A3. `.aidlc/audit.jsonl`: integrity and non-repudiation.
- A4. Command execution on the host machine: owner-configured prerequisite shell commands and `git`.
- A5. Local layout and identity: absolute paths, `HOME`, `git user.name`, the OS user, environment values.
- A6. Protocol channel integrity (stdout frames) and session availability.
- A7. The CLI's frozen behaviour and its offline `--locked` install (AC-001, AC-013).
- A8. The dependency supply chain (Cargo.lock).

## Trust boundaries
- B1. MCP host process to the stdio server. The host is trusted to launch the server, but every frame is parsed as untrusted bytes. The client picks the era on every request; neither era is more trusted, and `_meta` content (version, capabilities, `clientInfo`) is untrusted input.
- B2. Model-generated tool arguments. Untrusted and possibly prompt-injected.
- B3. Project filesystem and `.aidlc` state. Semi-trusted: it may come from a cloned repository, may hold hostile `config.json` prerequisites or symlinks, and the host's own file tools can edit it outside MCP.
- B4. A concurrent CLI process writing the same project.
- B5. Environment inherited from the host: `DTECH_AIDLC_HOME`, `PATH`, `HOME`, cwd. DeepSeek Harness passes a scrubbed parent environment (Observed, `<spike>/host-compat/dsh/transport.ts`).

## Entry points
- E1. stdin frames: legacy `initialize`, `ping` and `notifications/*`; modern requests carrying `_meta` (`io.modelcontextprotocol/protocolVersion`, `clientCapabilities`, `clientInfo`, `logLevel`, `progressToken`, unknown keys) on `server/discover`, `tools/list` and `tools/call`; `tools/*` in either era; and anything else a host sends (`resources/*`, `subscriptions/listen`, batches).
- E2. The four tool calls and their arguments: `status` (`intent_id`), `queue` (none), `next` (`claim`, `unit`), `report` (`stage`, `result`, `detail`, `approval`, `approved_by`, `approval_note`, `needs[]`, `unit`).
- E3. Launch argument `--project` and the cwd.
- E4. Environment variables (B5).
- E5. Project files read per call: `config.json`, state, `gate-recommendation.md`, the engine (embedded or external).
