# Implementation: WU-018 (Monitor server and CLI wiring)

- Status: Complete (build-and-verify, 2026-11-28). Cites FN-033, FN-034, FN-035, IF-018, IF-019, CFG-010, ADR-028, ADR-029, ADR-031, ADR-032, ADR-033.
- New `rust-cli/monitor/mod.rs`: `dtech-aidlc monitor` binds 127.0.0.1 on an ephemeral port, makes a per-run token from `telemetry::os_random` (fails closed), prints exactly one stderr line `monitor: http://127.0.0.1:<port>/#token=<32hex>  (Ctrl+C to stop)` (IF-019, ADR-028), writes nothing to stdout, refuses to start on an unsafe telemetry path without naming it; Ctrl+C uses default signal handling.
- New `rust-cli/monitor/http.rs`: std-only HTTP/1.1 server; ADR-032 ordered checks and status table with `{"error":"<code>"}` bodies, fixed security headers (CSP, nosniff, no-referrer, no-store, Connection: close) on every response and never any `Access-Control-*`; Host exactly `127.0.0.1:<port>` (localhost refused with 421, per IF-018 and the threat model); Origin and Sec-Fetch-Site exact; any method other than GET (any valid token, any case) is 405 with `Allow: GET`; static `/`, `/app.js`, `/app.css` without token; `/api/events` needs `Authorization: Bearer <token>` compared with `ct_eq` (length check, XOR fold through `black_box`) and calls `telemetry::query` with a shared cache; 16-connection cap (503 busy), 5 s total head deadline (408), 8 KiB head cap (431); panic guard gives 500 `internal_error` and frees the slot; Windows TimedOut and WouldBlock both count as timeouts.
- Stub assets `rust-cli/monitor/assets/{index.html,app.js,app.css}` (CSP-compatible; WU-019 fills them).
- CLI wiring: `monitor` in `args.rs`, `main.rs`, `help.txt`, `completion.zsh`, `COMMAND_KEYS` in `tests/repo_content.rs` and `tests/routing_golden.rs`.
- Goldens re-blessed with `DTECH_AIDLC_BLESS=1` in the baseline environment, monitor lines only: `utility_golden/help-and-completion.json` (help line and completion entry), `routing_golden/validation.json` (help line plus the two monitor validation steps `--no-such-option` and `extra0`), and `routing_golden/unsafe.json` (one added completion entry).
- Recorded deviations from IF-018 / CFG-010 (conductor decisions, AI Orchestrator): (1) `routing_golden/unsafe.json` is an eighth golden: it embeds the completion script, so the monitor completion entry adds one line; this falls under owner re-bless reason "monitor in help/completion/validation" (Q2/Q4); ADR-033's count of seven missed it. (2) Optional whitespace around the Authorization field value is stripped per RFC 9110; the `Bearer ` scheme and the token are still exact and case-sensitive. (3) The bounded drain (1 MiB or 1 s) runs before every error reply except 408 and 503, not only after a refused method, so 400/403/404/421/431 replies are also delivered when request bytes are pending.
