# AI threat-model review (AC-030)

## Purpose and status
- Purpose: this is the written threat-model review that AC-030 requires before release of intent 2. It covers MCP telemetry, the loopback `dtech-aidlc monitor` with its token and dashboard, and the installers. It is checked against the built code, not against the design.
- Status: an AI review under the AI orchestrator contract, done as an Analyze-gate follow-up. It is **not an owner approval**. The owner still decides the release gate. Where this record accepts a residual, that acceptance is the AI review's recommendation, and the owner may overturn it.
- Date: 2026-11-28.
- Code reviewed: commit `63852db` ("Build the monitor dashboard (WU-019)"). The working tree has uncommitted WU-021 documentation edits (README.md, CHANGELOG.md). Those edits are not part of the reviewed code. They are mentioned only where they bear on an open item.
- Inputs: [threat-model.md](../../../ideate/direction-selection/threat-model.md) (T2-01..T2-24), [decision-record.md](../../../ideate/direction-selection/decision-record.md) (ADR-019..ADR-039), [acceptance-criteria.md](../../../analyze/problem-framing/acceptance-criteria.md) (AC-030), [interfaces-and-contracts.md](../../implementation-design/interfaces-and-contracts.md) (IF-012..IF-020), and the build records WU-013..WU-020, including the three IF-018 deviations recorded in WU-018.
- Labels: **Observed** means seen in an experiment or read in the code at `63852db`. **Assumption** means not tested. **Estimate** means a qualitative rating. Every severity in this record is an Estimate (likelihood x impact on a local developer machine).
- Finding ids: T2-nn maps to an existing threat-model row. T2-22a..d are sub-findings of T2-22. NEW-n are findings that are not in the threat model; this record numbers them, and they are not registry ids.

## Method
1. **Five independent lens reviews.** Five reviews ran on Opus, one per lens: loopback-http, token, telemetry-privacy, dashboard-xss and installers. Each lens built `63852db` from `git archive` into its own `/private/tmp/threat-review-<lens>/` directory and ran the real release binaries against temp projects on 127.0.0.1. The browser lenses drove headless Microsoft Edge with an isolated `--user-data-dir`, and outbound traffic was blocked by a host-resolver map or a dead proxy. No repo file was edited and no external network was used.
2. **Adversarial verification of every high and medium finding.** No lens rated any finding High or Medium, so the verification set was **empty**. The one Medium item in scope, T2-06, is a planned by-design residual, not a finding.
3. **Orchestrator spot-check.** The orchestrator re-read the cited code at `63852db` for the findings marked CONFIRMED below:
   - `sink.rs:199-227` (no re-check at rollover)
   - `query.rs:346`/`:383` (lstat, then a whole-file read)
   - `install.sh:104-117` (trap and `status=$?`)
   - `http.rs:21` (CSP without Trusted Types)
   - `app.js:249-261` and `:404-410`/`:476` (plain-object lookups, shape check of the top level only)
   - `mod.rs:173-184` (`is_timestamp` checks shape only)
   - `index.html:23-24` (privacy text)
   - README and CHANGELOG at `63852db` (no "telemetry is not audit", no security-boundary text)
4. **Experiments (Observed; artefacts kept outside the repo):**
   - **loopback-http:** 56 raw-socket probes covering Host, Origin, Sec-Fetch-Site, methods, CL/TE, parsing, traversal and head cap. Slot exhaustion and drip timing (`exp/dos-results.txt`). A cross-origin attacker page and a DNS-rebinding navigation in Edge.
   - **token:** process output, argv and env. The page's storage and globals, checked over CDP. An Authorization probe matrix. A `ct_eq` timing benchmark (20M compares). The Edge History and Session files.
   - **telemetry-privacy:** a sentinel sweep through every tool argument and through malformed frames (`e1.py`). Symlink, prune and mode cases (`e2.py`). A mid-process swap of the directory for a symlink (`e7.py`).
   - **dashboard-xss:** 13 hostile and 9 valid seeded lines rendered in Edge. A stale-tab impostor on the freed port (`cdp2.mjs`, `fake.py`). A temp build with Trusted Types enforced.
   - **installers:** signal-window scenarios under bash-as-sh and dash with a PATH-shimmed slow `mv` (`run2.py`). Planted temp names. Ownership recognition. A tested fix in `fixed/install.sh`.

### Accepted without a finding (Observed unless stated)
- **T2-01, DNS rebinding: Negligible.** Every bad Host gives 421 or 400, and Edge rebinding `evil.test` to 127.0.0.1 got `host_rejected`.
- **T2-02, cross-origin and CSRF: Low.** All 56 cases had no `Access-Control-*` header. Origin and Sec-Fetch-Site violations got 403. Edge attacker fetches, `<script src>` and the iframe all failed. A page can still detect the listener, as planned.
- **T2-07, traversal: Negligible.** Every traversal form gave 404, and `?path=`, `?file=` and `%` gave 400.
- **T2-08, parser: Low.** CL/TE, obs-fold, NUL, HTTP/0.9 and HTTP/2 all gave 400. A pipelined request is ignored. A duplicate `Content-Length: 0` is accepted, which is harmless because the body is never read.
- **T2-11, protocol-error content: Negligible.** Secrets in unparseable frames left 0 hits.
- **T2-12, stdout: Negligible.** Monitor stdout was 0 bytes. The TS-023 guard is at `tests/telemetry_guards.rs:60`, and `on_error` carries a `&'static str`.
- **T2-14, forged events: Low.** 13 hostile lines were skipped and counted, and valid hostile-looking names rendered as text only.
- **T2-16, retention: Low.** A part measured 5,242,752 bytes against the 5,242,880 cap. The monitor never deletes.
- **T2-17, approval semantics, code side: Low.** `gate_decided` carries no approver and no decision. Sentinel sweeps gave 0 hits for `approved_by` and approval notes. The docs side is an open item.
- **T2-21, LAN exposure: Low.** The socket listens on 127.0.0.1 only, and a connection to the LAN address is refused. The firewall prompt is an Assumption.
- **T2-23, path disclosure: Negligible.** The response bodies contain 0 hits for the project path.
- **T2-24, outbound traffic: Negligible.** Only same-origin requests were made, with no Referer.
- **WU-018 IF-018 deviations.**
  - (2) OWS on Authorization: accepted, see T2-04.
  - (3) Wider bounded drain: accepted. It adds at most 1 s of slot hold and never stretches the head deadline.
  - (1) Eighth golden: outside the security scope. It is not reviewed here and stays with the owner re-bless record (Q2/Q4).
- **Default panic hook: Negligible.** No panic payload contains the token.

## Dispositions for the planned residuals
- **T2-03 (token in scrollback or browser history): accepted, Low.** Downgraded from the planned Low-Medium. The behaviour is now Observed on Chromium, no longer an Assumption: History with `typed_count`, the Session file and `userTypedURL` all keep the token URL. The only extra reader is the same OS user (T2-06), or an off-host copy through history sync, where the token is useless. Moving the token out of the URL would break the owner-chosen Option A UX (Q7), and ADR-029 reopens that only if this residual is rated High. Condition: the README disclosure (open item 1).
- **T2-05 (Windows inherited ACLs): accepted.** Low-Medium on Windows, Low on Unix. The Unix modes 0o700/0o600 are Observed. On Windows the marginal exposure is small, because `.aidlc/state.json`, the audit log and the artifacts already share the same ACL from intent 1. The dashboard already discloses it (`index.html:21`). Conditions: a README line advising a user-profile location or a restricted folder ACL, and windows-latest CI. The Windows ACL behaviour and port takeover by another user stay Assumptions.
- **T2-06 (same-user process): accepted by design, Medium.** No token scheme can defend against the user's own account. That account can read `.aidlc/telemetry`, the terminal and the browser profile directly, and every lens confirmed this. Condition: the README security-boundary sentence is committed. It is absent at `63852db` and present only uncommitted in the working tree (`README.md:464`).
- **T2-10 (intent ids are slugs of user text): owner-accepted (Q13), Low-Medium; the data is accepted, the disclosure condition is not yet met.** Observed: the slug of the intent text "Rotate api key hunter2 for alice" is stored. The owner's acceptance was conditional on disclosure under AC-020. At `63852db` the privacy text says "Never kept: prompts" and nothing says the intent id comes from the typed text. The wording fix in finding T2-10 must land before this acceptance counts.
- **T2-15 (writer drops make metrics incomplete): accepted, Low, disclosed.** `try_send` never blocks a reply. The first drop prints one fixed line.
