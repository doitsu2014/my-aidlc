## Round 1 issues (all fixed in the pack, see pack section 7)

1. IMPORTANT (AC-021, s2 'Recent events' row): the page announces auto-refresh 'on change of count or state'. In an active session the count changes on most 5 s polls, so the polite live region would speak every 5 s. AC-021 requires refresh results to be 'announced once'. Required: announce only the result of a manual Refresh, Apply, Clear or Load older, plus state transitions such as entering stale, error, quiet or empty. Never announce an auto-refresh that only changes the count.
2. IMPORTANT (AC-021 keyboard operability, s2 'Recent events: Unchanged', s5.3 step 8): the pack does not say how the list is re-rendered every 5 s. Rebuilding the <ol> removes the focused row button and drops focus to <body> every poll for a keyboard or screen-reader user. Required: key row elements by eventId, reuse existing nodes, insert new rows without replacing the focused element, and if the focused row is gone (it aged out of the page) move focus to the Events heading. Add this to the TS-030 checklist: keyboard focus on a row survives 3 auto-refreshes.
3. IMPORTANT (state machine contradiction, s1.3 paging vs s2 Stale row): while older pages are loaded auto-refresh is paused, but Stale fires when the 'last success [is] older than 15 s'. Within 15 s of paging, the user would see '! STALE: last updated ...' although nothing failed and they chose the pause. Required: a user-paused state ('Auto-refresh paused while older events are shown' plus [Back to newest]) takes the place of the time-based stale banner. Stale by age applies only while auto-refresh is supposed to run. Put the paused state in the s2 matrix and in the precedence order.
4. IMPORTANT (s2 Error row, s1.3 client check): 400 invalid_filter and 400 range_too_large go into the retrying Error state with backoff 5-60 s. The same GET is deterministic, so it fails forever and keeps sending the token. The proposed client regex is also wider than the Observed server-side id charsets (tools.rs:73-74, IF-012), so a typed 'a.b' or 'A_B' stage reaches the server and triggers this loop. The hint text ('letters digits . _ -') is wrong too. Required: a 4xx other than 401 and 409 does not retry. Show 'Request failed: a filter value was rejected', keep the last data marked stale, put focus on the filter form only if a user action caused it, and wait for a user action. Replace the client check with per-field rules: stage ^[a-z0-9-]{1,64}$, session ^[0-9a-f]{32}$, trace ^[0-9a-f]{32}-[0-9]+$ with at most 64 characters, all subject to WU-017 confirmation. Fix the hints to match.
5. IMPORTANT (FN-042 / ADR-038 scope of WU-016, mock not finished): the mock diff makes only the title, h1 and font changes. The FN-042 / ADR-038 edits that WU-016 owns are still missing (Observed in plans/mcp-server-enhancement/mcp-studio-server.html): shipped tool names; 'TELEMETRY MCP-ONLY · DEFAULT ON · OPT-OUT' (line 149 still reads 'TELEMETRY DEFAULT UNDECIDED'); operation events labelled as MCP-caller only; the guardrail at line 218 still says 'Monitor is a separate process ... returns independently'; principles at lines 239-240 still leave the token and retention 'open' instead of stating the fragment token and the 5 MiB / 7 days / 50 MiB values; the line 229 approval wording is not ADR-013 wording. WU-022 touches the mock only for the 'proposed' label, so these edits are lost if WU-016 closes now. They are not a dashboard design defect, but WU-016 must not record done until they are made or the owner explicitly defers them. The mock passes the remote-URL check: grep finds no http(s)://, googleapis, gstatic or 'Orca' (Observed). The only url() uses are internal SVG marker fragments such as url(#arrow-ink), which are allowed.
6. Minor (missing states, s1.6 / s2): 'Error' and 'Unavailable' on the first request have no last-known data, but the copy says 'Last data from ... shown, marked STALE' or 'Last-known data shown'. Add first-load variants ('No data loaded yet') for Error, Unavailable and Monitor stopped.
7. Minor (T2-20 hardening, s2): a hidden tab pauses polling, so a monitor exit can go unnoticed. When the tab becomes visible, one GET may reach a different process now on the same port. A 404, HTML or non-JSON reply then enters the retrying Error state and keeps sending the dead token. Treat 'unexpected response' (wrong content type, unparseable body, schemaVersion other than 1, unknown error code) like Monitor stopped: stop auto-refresh and offer manual retry only.
8. Minor (AC-021 colour alone, s3.1): the selected row is marked only by the --surface-2 background. Add a non-colour cue (a visible marker or border plus aria-current="true" on the row button), and set aria-describedby on invalid fields so the inline error message is linked to the field.
9. Minor (glyphs, s1.1 glyph key): the 'no-entry sign' (U+1F6AB), and on some platforms the warning (U+26A0) and information (U+2139) signs, render as colour emoji. Emoji ignore the status colour tokens and the computed contrast. Name exact code points with text presentation (for example U+2713, U+2298, U+2715, U+25CB, U+26A0 U+FE0E, U+2139 U+FE0E), mark glyphs aria-hidden, and keep the word as the accessible name.
10. Minor (s5.3, no-data states): in Token missing and Token rejected the skip link 'Skip to events' points to an Events heading that is not rendered, yet the matrix says the first Tab reaches it. Hide the skip link in no-data states or point it at the banner. Also, a live region that already holds its text at page load is often not announced. Insert the Token missing text into the existing status region after load.
11. Minor (wireframe fidelity, s1.2): the 320 px drawing leaves 'files read' and 'kinds not observed' out of the coverage line and drops the 'no approve/reject value' qualifier from Gate decisions. The narrow layout must carry the same content as the wide one, only wrapped.
12. Minor (accessible names, s1.1 / s5.1): the list has no <table>, so the visual column headers have no semantics. Define each row button's accessible name in a fixed order (time, source, event, name, duration, outcome), for example '15:03:10, MCP, mcp.tool.completed, report, 86 ms, Blocked'.
13. Minor (s1.4 Go to parent): say explicitly that the trace lookup query does not change the active filters or the visible list, only the detail panel. Say also that 'Show this session' clears an active trace filter, and 'Show this trace' an active session filter, so the two cannot combine into an empty result by accident.
14. Nit (implementation notes for WU-019): keep TOKEN inside an IIFE or a type="module" script, because a top-level const in a classic script is a global lexical binding. Handle Apply through a 'submit' listener with preventDefault, since the CSP 'form-action none' blocks native submission. Never use setAttribute('style'), which 'style-src self' blocks. Scope overflow-wrap:anywhere to ids and codes, not the whole body. Make the Filters <details> open at 960 px and above without hiding content. Add a forced-colors check to the TS-030 checklist.
15. Nit (s1.5): 'The panel never shows a path' should say 'never shows an absolute path'. The panel deliberately shows the generic relative location '.aidlc/telemetry/' that AC-020 requires.

## Round 2 (acceptance) remaining nits, applied by the conductor

1. Nit (WU-019 implementation, response ordering): the pack does not say what happens when an earlier request's reply arrives after a later user action. Example: an auto-refresh with the old filters is in flight when the user presses Apply, Load older or Back to newest. If it returns last, it can overwrite the newer result, or leave the paused state with a page-1 list. Add to s5.4: give each query a sequence number, or abort the in-flight request (AbortController), and ignore any reply that is not from the latest request.
2. Nit (wireframe fidelity, s1.6 Token missing): the s2 matrix says Setting unknown and liveness unknown are always shown in the header, and that Token missing shows the header and privacy panel. The Token missing drawing omits 'read-only', 'Setting: unknown' and 'MCP process: unknown'. Draw the full header lines, or state that the header is the same as in s1.2.

Both nits are now in the pack: section 5.4 (request sequence numbers and AbortController) and section 1.6 (Token missing header lines).
