It is the input to the AI threat-model review that AC-030 requires before release. That review, not the owner at the solution-direction gate, accepts each residual risk or requires a change.

## Assets
- A1. Telemetry files `.aidlc/telemetry/mcp-*.jsonl`: event ids, timings, outcomes, error codes, pids and validated intent/stage/unit ids (slugs of the user's intent text; R5, Q13).
- A2. Project paths and local layout (absolute paths, user name in paths): never stored, never served; the dashboard header says "local project".
- A3. The per-run monitor token (16 bytes from the OS random source): read access to A1 through the monitor for the life of the process.
- A4. Workflow state, audit log and artifacts under `.aidlc/`: telemetry never reads, locks or writes them; the monitor never reads them (AC-007, AC-016).
- A5. MCP stdout protocol integrity and the unchanged tool replies (AC-010, AC-028).
- A6. Dashboard page integrity in the browser (the page holds A3 in memory).
- A7. Installed binaries and the install prefix (AC-026).
- A8. The honest meaning of telemetry: not audit, approver names self-asserted, metrics complete only as disclosed (AC-018, AC-030).

## Trust boundaries
- B1. Browser (any origin, any tab) to the loopback monitor server. Every request is untrusted until Host, Origin, Sec-Fetch-Site, route and token pass.
- B2. Other OS accounts and their processes on the same machine to the loopback port and the telemetry files. The loopback interface is shared by every account. Same-user processes are inside the boundary: they can read the terminal, the files and the browser, and this is accepted and documented, not mitigated.
- B3. MCP host and model-generated arguments to `dtech-aidlc-mcp` (as in intent 1). Arguments, frames and tool names are untrusted input to the event hook.
- B4. Filesystem content to the writer and the reader. `.aidlc/telemetry` may come from a cloned repository (a git-ignore line does not stop a force-added commit), may be a symlink, or may hold crafted lines.
- B5. Installer to the prefix and to processes running from it.

## Entry points
- E1. HTTP on `127.0.0.1:<ephemeral>`: `GET /`, `/app.js`, `/app.css`, `/api/events?range&component&name&outcome&stage&session&trace&limit&cursor`; any other method, target or header combination.
- E2. The URL fragment `#token=` read by `app.js`, and the `Authorization: Bearer` header read by the server.
- E3. MCP stdin frames and tool arguments that reach the event hook and the `on_error` observer.
- E4. Files and directories under `.aidlc/telemetry/` read by the query engine and pruned by the writer.
- E5. Launch arguments: `dtech-aidlc-mcp --project`, `--telemetry on|off`; `dtech-aidlc [--project] monitor`.
- E6. `install.sh` and `install.ps1` arguments and the state of the prefix.

## Threats
| Element | STRIDE | Threat | Mitigation | Residual risk |
|---|---|---|---|---|
| T2-01 Monitor server, Host check (A1, A3; B1, E1) | S, I | DNS rebinding: an attacker page rebinds its hostname to 127.0.0.1 and reads `/api/events` as same-origin. Likelihood Medium (generic technique), impact High. | Bind `127.0.0.1` only; Host must equal `127.0.0.1:<port>` exactly, `localhost` refused, else `421 host_rejected`; token still required and the attacker never sees the fragment; ephemeral port (ADR-027, ADR-029, ADR-032). Verify: raw `TcpStream` with Host `evil.example:<port>`, `localhost:<port>`, no port, missing Host gives 421 (Observed in `<spike2>/http/results.txt` for foreign, no port and missing Host). AC-015. | Negligible. |
| T2-02 Monitor server, cross-origin and CSRF (A1, A6; B1, E1) | I, T | A foreign page uses `fetch`, `<script src>`, `<img>` or a form against the port; no-cors GETs carry no Origin. Likelihood Medium, impact Medium. | No `Access-Control-*` header ever; the Bearer header forces a preflight, which gets `405` without CORS headers; no-cors requests cannot carry the token, so `/api/*` gives 401; Origin present and not `http://127.0.0.1:<port>` (including `null`) or Sec-Fetch-Site not `same-origin`/`none` gives `403 origin_rejected`; `Cross-Origin-Resource-Policy: same-origin`; CSP `frame-ancestors 'none'`; no state-changing route, so CSRF has no target (ADR-032; AC-014). Verify: Origin `http://evil.example` and `null` give 403; Sec-Fetch-Site `cross-site` gives 403; OPTIONS and POST/PUT/PATCH/DELETE give 405 with no CORS header and an unchanged `.aidlc` snapshot. AC-014, AC-015. | Low: a page can detect that something listens on a port by timing or `onerror`, but reads nothing. |
| T2-03 Token delivery and page storage (A3; B1, B2, E2) | I | Token leaks through terminal scrollback, CI logs, screen sharing, browser global history or autocomplete, Referer, server logs, argv or env. Likelihood Low-Medium, impact Medium (read access to telemetry metadata only). | Token only in the stderr startup line, inside the fragment; never in argv, env, files, telemetry, MCP output or per-request logs; the fragment is not sent in the request line or Referer, and `Referrer-Policy: no-referrer`; `app.js` keeps it in a closure `const`, calls `history.replaceState(null,'','/')` before the first fetch, never uses sessionStorage, localStorage, cookies, IndexedDB, the DOM or a global; reload shows "Token missing"; token dies with the process and the port changes each run (ADR-028, ADR-029). Verify: grep the store and MCP stdout for the token (0 hits); 20 malformed requests leave stderr equal to the single startup line; page test asserts empty `location.hash`, empty storage and `document.cookie` after load; `ps` argv lacks the token. AC-019, AC-030. | Low-Medium: while the monitor runs, a copy in scrollback, or in browser history recorded before `replaceState`, stays valid (browser behaviour is an Assumption, not tested). Browser extensions are same-user (T2-06). |
| T2-04 Token check (A3; B1, B2) | S | Guessing the token, or recovering it by timing the comparison. Likelihood Very low, impact Medium. | 128 bits from `/dev/urandom` or `BCryptGenRandom`, fail closed with exit 1 and no fallback generator; length check then XOR fold over all bytes through `std::hint::black_box`; same `401 unauthorized` body for missing, malformed and wrong; 16-connection cap limits guess rate (ADR-029, ADR-032). Verify: `ct_eq` unit tests (equal, last byte different, short; Observed in `<spike2>/decide/token.rs`, which also showed no timing difference between first- and last-byte mismatch over 5M compares); windows-latest test of 10k unique 32-hex tokens. AC-030. | Negligible. Windows: Assumption until CI links and runs bcrypt. |
| T2-05 Other OS users (A1, A3; B2) | S, I | Another account on a shared machine connects to the loopback port or reads telemetry files. Likelihood Low-Medium, impact Medium. | Token required for data (T2-04); Unix directory 0o700 and files 0o600 with `create_new` (ADR-020); token not in argv, so `ps` does not reveal it. Verify: Unix mode-bit assertions on created directory and files; argv check. AC-008, AC-020, AC-030. | Low-Medium on Windows: telemetry files inherit the project directory's ACLs, so a project in a shared folder may be readable by others (Assumption; disclosed in README and the AC-020 privacy help). Other users can see that a port listens. |
| T2-06 Same-user process (A1, A3, A6; B2) | I, T | Any process running as the same user reads the terminal, the telemetry files, browser memory or extensions. Likelihood n/a (inside the boundary), impact Medium. | None by design: the token does not protect against the same user, who can read `.aidlc/telemetry` directly. Stated in the README security boundary and recorded in the AC-030 review (ADR-029). Verify: README content check. AC-030. | **Medium, accepted by design**; the AC-030 AI threat review confirms the acceptance before release (not an owner gate item). |
| T2-07 Static routes and store reader, traversal (A2, A4; B1, B4, E1, E4) | I | Path traversal through the URL or a query parameter reads files outside `.aidlc/telemetry`. Likelihood Low, impact High. | Exact route table on the raw target with no percent-decoding and no filesystem mapping; assets embedded with `include_str!`; any `path`/`file` key or `%` in the query gives `400 invalid_filter`; the reader lists the directory itself and opens only pattern-matching regular files via `symlink_metadata` (ADR-028, ADR-031, ADR-032). Verify: `/../etc/passwd` (`curl --path-as-is`), `/%2e%2e/etc/passwd`, backslash forms, `/app.js/../x`, `//etc/passwd` give 404; `?path=/etc/passwd`, `?file=x` give 400; a fixture proves no file outside the store is opened. AC-016. | Negligible. |
| T2-08 HTTP parser (A5 of the monitor; B1, E1) | T, D | Request smuggling or parser confusion: CL+TE, negative or huge Content-Length, obs-fold, NUL or UTF-8 in the target, duplicate Host, HTTP/0.9 or 2. Likelihood Low, impact Medium. | GET only; the body is never read; Content-Length other than 0, any Transfer-Encoding, or duplicate Host gives `400 bad_request`; non-ASCII or control bytes and unsupported versions give 400; one request per connection, `Connection: close`; no proxy role; method checked before body headers so AC-014's method error holds (ADR-027, ADR-032; R9). Verify: parser table tests for each case; a refused method with a 2 MiB body still receives its reply (Observed, `<spike2>/http/shutdown-results.txt` case D). AC-014. | Low: maintainers own a hand-rolled parser; the table tests are the control. |
| T2-09 Connection handling (monitor availability; B1, B2) | D | Slowloris, oversized heads or connection exhaustion make the dashboard unavailable. Likelihood Medium, impact Low (local, read-only). | 5 s total head deadline (`408`); 8 KiB head cap (`431`); 5 s write timeout; 16 connections then `503 busy`; per-connection panic isolation with a Drop guard (ADR-027, ADR-032). Verify (Observed on macOS, `<spike2>/http/results.txt`): 20 KB head gives 431; one byte per second gives 408 at 5 s; 40 idle sockets give 503 then recovery; 200 concurrent valid requests succeed. Re-run as contract tests on both OSes. AC-013, AC-014. | Low: a local client that renews 16 sockets every 5 s can keep the dashboard busy; accepted. |
| T2-10 Event hook and store, privacy (A1, A2; B3, E3) | I | Arguments, free text, approver names, paths, env values or unknown tool names end up in the store or in monitor responses. Likelihood Medium without controls, impact Medium. | Explicit field-by-field constructor to the AC-002 set, never a generic value; ids stored only if they pass the `tools.rs` validators and 64-character caps; unknown tool stored as `unknown`; never stored: `detail`, `approved_by`, approval note, messages, paths, argv, env, raw frames; error codes from fixed enumerations; the monitor re-serialises only allowlisted fields; header says "local project" (ADR-024, ADR-030). Verify: AC-002 field-for-field check; sentinel values through every tool give 0 hits in the store and in responses. AC-002, AC-020. | Low-Medium: intent ids are slugs of the user's intent text, plus pids and timings (**owner-accepted**, Q13); disclosed under AC-020. |
| T2-11 Protocol-error observer (A1; B3, E3) | I | A malformed or oversized frame containing a secret is recorded in telemetry with its content. Likelihood Medium, impact Medium. | `on_error: fn(&C, &'static str)` carries only a static code chosen by `serve`; the type cannot carry frame text; reply bytes unchanged (ADR-025). Verify: AC-005 "Content excluded" scenario with a secret in an unparseable and in an oversized line gives 0 hits and distinct codes `parse_error`/`line_too_long`. AC-005. | Negligible. |
| T2-12 MCP stdout (A5; E3) | T, D | Telemetry output or a diagnostic is written to stdout and corrupts protocol frames. Likelihood Low, impact High. | `serve` stays the only stdout writer; telemetry writes files and at most one fixed stderr line per condition; CI guard greps `rust-cli/` for stdout writes outside `serve` (ADR-021, ADR-025; R4). Verify: AC-028 transcripts with telemetry on, off, failing, panicking and stalled are byte-identical on stdout. AC-028. | Negligible. |
| T2-13 Store location, symlink planting and tampering (A1, A4; B4, E4) | T, I | A cloned repo or another process plants a symlinked `.aidlc/telemetry` or file, so the writer writes through it or prune deletes its target, or the reader follows it. Likelihood Low-Medium, impact Medium. | Writer never creates `.aidlc`; checks `.aidlc` with `assert_safe_state_dir` and `.aidlc/telemetry` with lstat; `create_new` refuses an existing path or final-component symlink; prune touches only pattern-matching regular files and never follows links; monitor refuses an unsafe directory at start, re-checks per query, ignores symlinked files (ADR-020, ADR-028). Verify: AC-008 symlinked-directory scenario (no write through the link, one stderr line); AC-016 symlinked-file scenario; prune leaves unrelated files and link targets intact (Observed in `<spike2>/review/tspike` for the unrelated file). AC-008, AC-009, AC-016. | Low: an lstat-to-open race by a same-user process (T2-06), limited by the 0o700 directory; a followed file must still parse as allowlisted events to show anything. |
| T2-14 Forged events to dashboard script (A6, A3; B4 to B1, E4) | T, E | A crafted line with HTML or script in `name`, `stageId` or `errorCode` executes in the page that holds the token. Likelihood Low-Medium, impact High. | Reader re-validates every field (types, enumerations, id character set, lengths) and drops invalid lines as skipped; UI writes only through `textContent`, with no `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval`, `new Function` or inline handlers; CSP `script-src 'self'`, `style-src 'self'`, no `unsafe-inline` or `unsafe-eval`; `nosniff` (ADR-030, ADR-031, ADR-032). Verify: fixture with markup in each string field is skipped and counted; DOM test asserts no injected element; repo-content test scans `app.js` for the banned APIs. AC-003, AC-016, AC-030. | Low: forged events that pass the schema display as real; the dashboard is not audit (T2-17). |
| T2-15 Telemetry sink under load or failure (A5, A8; B3) | D, R | A flood of calls or a stalled disk blocks replies, or drops events so metrics look complete when they are not. Likelihood Medium, impact Low-Medium. | Producer uses `try_send` only on a 1024 queue, so the reply never waits on disk; first drop prints one fixed stderr line; any writer failure disables telemetry for the process; the coverage line says "Dropped events: not recorded" and a dropped completion shows as incomplete, never success (ADR-021, ADR-030). Verify: injected 10 s writer stall, reply under 1 s (spike: 1000 sends in 0.39 ms with a stalled writer, Observed `<spike2>/review/tspike`); simulated writer panic leaves the server alive. AC-010, AC-018, AC-028. | Low: AC-004 and AC-018 are Met* (met while the queue does not fill), a gate condition; drops are disclosed, not counted. |
| T2-16 Retention (A1; B3, E4) | D, I | Store grows without bound (flood, Windows delete failures) or keeps data longer than disclosed. Likelihood Medium, impact Low-Medium. | 5 MiB per part, 7 days by mtime, 50 MiB total; prune at writer start and each rollover; read caps on the monitor; expired files counted, not shown (ADR-020, ADR-028, ADR-030). Verify: 10,000 calls keep the total under the cap plus one part per live process; expired fixture files are not shown and are counted. AC-009, AC-017. | Low: overshoot of one open file per live process between prunes; Windows delete-pending behaviour is an Assumption (R7); the monitor never deletes, so expired files stay until a telemetry-on MCP process next writes its first event or rolls over (ADR-020). |
| T2-17 Meaning of `workflow.gate_decided` (A8) | R | A reader treats telemetry, or `gate_decided`, as proof of who approved a gate. Likelihood Medium, impact Medium. | `gate_decided` carries no approver and no approve/reject value; audit log and state stay the record; README and CHANGELOG say "approver names are self-asserted" and "telemetry is not audit" (ADR-024, ADR-033, ADR-034; intent-1 ADR-013). Verify: repo-content check for both sentences in README and CHANGELOG. AC-030. | Low; forged events covered by T2-14. |
| T2-18 Git exposure of the store (A1; B4) | I | Telemetry is committed and pushed because the managed ignore block lags (R2). Likelihood Medium without controls, impact Medium. | Writer creates `.aidlc/telemetry/.gitignore` containing `*` on directory creation, plus a `/telemetry/` line in IGNORE_BLOCK (ADR-020). Verify: `git status --porcelain` in a fixture repo after telemetry is written shows nothing under `.aidlc/telemetry`; golden review of the one IGNORE_BLOCK line. AC-008. | Low: a user can still force-add (`git add -f`); out of the tool's control. |
| T2-19 Random source FFI (A3; Windows) | E, D | The new unsafe `BCryptGenRandom` call misbehaves, or the random source fails and a weak token is used. Likelihood Very low, impact Medium. | About 8 lines of unsafe with a fixed 16-byte buffer and a SAFETY comment, following the kernel32 precedent (`rust-cli/dependencies.rs:338-361`, Observed); negative NTSTATUS is an error; fail closed (monitor exits 1, MCP disables telemetry); no fallback generator (ADR-026, ADR-029). Verify: windows-latest token test. AC-010, AC-013. | Low. Windows: Assumption until CI builds and runs it (never compiled: the `cfg(windows)` item is skipped on macOS, the only platform built so far). |
| T2-20 Stale tab after monitor exit (A3, A6; B2) | S | The monitor exits; another process binds the same port; a still-open tab keeps polling, sends the dead token and renders attacker JSON. Likelihood Low, impact Low. | Page stops auto-polling on a network error and shows "Monitor stopped or unreachable" (manual retry only); data rendered as text only; token already dead (ADR-028, ADR-030). Verify: UI test kills the server, sees the stopped state, and asserts no further requests. AC-017. | Low. |
| T2-21 Firewall and LAN exposure (monitor availability; B1) | I, D | The listener is reachable from the network, or a firewall prompt leads the user to allow it. Likelihood Low, impact Low-Medium. | Bind `127.0.0.1` only, never `0.0.0.0` (ADR-027). Verify: CI asserts the listening address (lsof/netstat); a LAN-address connection is refused (Observed on macOS, `<spike2>/http/results.txt`); one manual Windows desktop check for a firewall prompt. AC-014, AC-029. | Low. Assumption that a loopback-only listener raises no Windows Defender or macOS firewall prompt (ASM6). |
| T2-22 Installers (A7; B5, E6) | T, D, E | Upgrade or uninstall deletes the wrong directory, leaves a half-installed prefix, or the rollback path at `install.ps1:80`/`:87-88` (Observed) deletes the new install when cleanup hits a locked exe. Likelihood Medium, impact Medium. | Marker `v2` recognition; uninstall removes only recognised files; stage, rename and rollback (Observed `install.sh:121-125`, `install.ps1:76-93`); Windows preflight refuses to change anything while an installed exe runs, with a clear message; post-commit cleanup best-effort outside the try block, leftovers removed by name on the next run; nothing downloaded (ADR-035). AC-026. | Low, but Windows: Assumption that a running exe cannot be deleted and that `Get-Process` exposes its path, until CI. Prefix permissions are the user's choice (documented). |
| T2-23 Responses and diagnostics (A2) | I | Error bodies, stderr lines or the dashboard header reveal paths or echo input. Likelihood Low, impact Medium. | Fixed JSON error codes with no input echo and no paths; telemetry and monitor stderr lines are fixed text without paths; header reads "local project" (ADR-021, ADR-028, ADR-032). Verify: exact body assertion for each of the 14 error codes, plus the `limitReached` flag on a 200; header never contains the project path, including a path with a user name. AC-016, AC-020. | Negligible. |
| T2-24 Outbound network (A1, A2) | I | Dashboard or binaries load remote fonts or scripts, or send data off the machine. Likelihood Low, impact Medium. | No outbound code; assets embedded; system font stacks; CSP `default-src 'none'` with `connect-src 'self'`; Studio mock drops Google Fonts (ADR-031, ADR-038). Verify: asset scan for remote URLs; run with outbound traffic blocked. AC-011. | Negligible. |
