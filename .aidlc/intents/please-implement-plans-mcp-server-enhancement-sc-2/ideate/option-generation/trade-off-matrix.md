# Trade-off matrix: intent 2 solution options

Purpose: compare Options A-D from `solution-options.md` against the criteria the owner and the Analyze baseline care about, with each cell justified, so the direction-selection stage and the owner can choose without another discovery meeting. This artifact does not select a direction.
Status: Draft - pending solution-direction gate

## Options in one line each

- **A** - Background bounded writer, hook in the MCP adapter, tests pass `--telemetry off`; in-process foreground `dtech-aidlc monitor`; hardened std HTTP with server-side query and cursor; 128-bit OS-RNG token in the URL fragment, then Bearer.
- **B** - Plan-literal: synchronous sink with a disable latch, operation hook in `application.rs` (no-op for the CLI), optionally, snapshot helper skips `.aidlc/telemetry` (owner written approval needed; otherwise the `--telemetry off` test flag as A); supervisor with env-var hidden child that exits on stdin EOF; same server; OS-RNG token typed into the page (never in a URL).
- **C** - Lean: telemetry as A; in-process monitor; same hardened server and A's two embedded files (`script-src 'self'`), one bounded data route, filtering and paging in the browser; no token.
- **D** - Static snapshot: telemetry as A; `dtech-aidlc monitor` prints one self-contained HTML report to stdout; no server.

Work common to every option (release 1.3.0, CHANGELOG, README, installers, flaky tests, missing intent-1 MCP tests, `deps add` lock, studio HTML, AI design and threat reviews, monitor CLI surface, event vocabulary, error mapping, retention, location, opt-out flag) is identical and is excluded from the comparison below (solution-options.md section 1). Its effort is about 4-5 dev-days (Estimate) in every option.

The bundles are not the only choices. Write path, operation hook, test isolation, monitor process, query and token are independent axes (solution-options.md section 2, axis table). In particular, B's Q24 snapshot skip is optional, and a synchronous writer works with the adapter hook and the `--telemetry off` test flag. The rows below rate the four named bundles. The last subsection rates the main unbundled combination.

## Summary

- **A** covers the most acceptance criteria with no owner-gated condition. Of the named bundles, it is the only one that combines all three: AC-028's "write stalls" scenario met, the server-bound cursor, and a per-run token. C and D also meet the write-stall scenario because they use A's telemetry, but C has no token or server cursor and D has neither. A's own conditions are that the queue must not fill silently: AC-004, AC-018 and AC-020 are Met* until drops are counted or disclosed. The cost is three plan deviations to record as ADRs (in-process monitor, token in the fragment, adapter hook), unverified Windows FFI and firewall behaviour, and mid-range effort.
- **B** is closest to the plan text and keeps tokens out of URLs. It follows ADR-006's hook note but reopens ADR-006 (per-process sink state in the facade). It costs the most, carries the most Windows uncertainty (supervisor/child), and weakens AC-028 scenario 4 through synchronous writes (AC-010 stays Met). It needs owner written approval only if its optional Q24 snapshot skip is chosen.
- **C** is the cheapest option that still serves a live monitor. It trades the per-run token (shared-machine exposure, which the AC-030 review would have to accept) and the server-bound cursor (AC-019 Partial) for less code.
- **D** has the smallest security surface and cost but fails AC-013 and AC-017, would leave an at-rest telemetry copy outside retention, and would need Analyze-owned acceptance criteria to change.
- **Unbundled combination worth showing:** a synchronous writer + adapter hook + `--telemetry off` test flag, with C's (or A's) monitor. It is the cheapest live combination (Estimate: C's effort less about 0.25 day). It has no thread, no silent drops (AC-004/AC-018 drop condition gone), no owner-gated test change and no ADR-006 reopen. Its one cost is AC-028 scenario 4 Partial unless the owner sets the stall bound to the OS write time, which is the same trade B makes.
- **Shared by every option:** AC-017's "off (trusted input only)" state cannot appear in v1 (Q20; compliant on the alternative reading), "shutting down" is client-detected (R13), tool calls rejected before the tool host give no tool span (AC-004 interpretation), the monitor treats absent telemetry as the empty state and counts expired-but-present files (proposal), and Windows behaviour (delete-pending prune, installer exe locking, firewall prompt) needs windows-latest CI and one manual desktop check. Q14 thresholds are Estimates that direction-selection must fix.
- **Infeasible variants** (crate-based HTTP, an MCP-hosted monitor, CLI telemetry, default off, an unapproved snapshot skip) are listed in solution-options.md section 4 and are not compared here.

No direction is selected. The decision-facilitator should present these options at the solution-direction gate.
